# Release v1.0.2 - Unbound Variables on the Boot Path

**Release date:** 2026-08-22
**Previous version:** 1.0.1

## Summary

A follow-up to 1.0.1, found by the same reboot test. With the logging abort out
of the way, `oradba_services_root.sh` ran far enough to reveal the next defect:
`oradba_lsnrctl.sh` tested `${TNS_ADMIN}` without a default and aborted under
`set -u`, so the listener never started and the systemd unit failed.

The interesting part is why nobody hit this by hand. An interactive shell has
sourced the oradba profile, so `TNS_ADMIN`, `ORACLE_HOME` and `ORACLE_SID` are
all present. systemd starts through `su - oracle -c ...` with a minimal
environment and no profile. A service script verified from an interactive
session therefore proves nothing about boot.

This release also completes the 1.0.1 logging fix, which stopped the abort but
still printed one redirection error per log call.

## Changes

### Fixed

- 29 tests on environment variables across eight files now use `${VAR:-}`:
  `oradba_lsnrctl.sh`, `oradba_check.sh`, `oradba_setup.sh`,
  `oradba_sqlnet.sh`, `oradba_rman.sh`, `oradba_extension.sh`, `dbstatus.sh`
  and `oradba_common.sh`. `${VAR:-}` is behaviour-preserving for `-z` and `-n`;
  the only change is that the script no longer dies. Script-internal variables
  were left untouched.

- `_oradba_log_to_file`: the file write is wrapped in a group so that
  `2> /dev/null` actually suppresses a failing redirection. In 1.0.1 this
  produced one `Permission denied` line per log call when `${ORADBA_LOG}` was
  not writable.

### Added

- `doc/development.md`: "Environment Variables Under `set -u`".
- `src/doc/troubleshooting.md`: the `TNS_ADMIN: unbound variable` signature.

## Upgrade Notes

Recommended for every host that starts Oracle through systemd or init.d.
Together with 1.0.1 this is what makes an unattended boot work at all.

Create the log directory and hand it to the Oracle user, otherwise the service
logs stay empty:

```bash
sudo mkdir -p /var/log/oracle
sudo chown oracle:oinstall /var/log/oracle
sudo chmod 755 /var/log/oracle
```

## Known Limitations

### Seven pre-existing test failures

`bats -r tests/` reports 7 failures out of 1720. They are **not** introduced by
this release: a run against the `v1.0.1` tag produces the identical list.

```text
not ok  installer has preserve_configs function
not ok  generate_sid_aliases creates rlwrap aliases when rlwrap is available
not ok  sqh alias connects with sysdba when rlwrap available
not ok  show_status calls setup_connector_environment
not ok  oradba_version.sh --info shows comprehensive information
not ok  datasafe_plugin.sh supports ORADBA_CACHED_PS environment variable
not ok  datasafe_plugin.sh falls back to ps -ef when no cache
```

Worth noting separately: neither CI nor the release workflow blocks on a red
suite, which is how these reached a tagged release unnoticed. Both the failures
and that gate belong in a follow-up.

### Remaining bare-variable tests

Around 70 further bare-variable tests remain in `src/bin/`. They cover
script-internal variables that are initialised before use and are not reachable
as unbound. A deliberate sweep is worth doing, but it is a refactor, not a
hotfix, and was kept out of this release.
