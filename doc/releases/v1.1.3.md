# Release v1.1.3 - GitHub Errors Say What Went Wrong

**Release date:** 2026-10-16
**Previous version:** 1.1.2

## Summary

A patch release for issue #234: `oradba_extension.sh add` hid failed GitHub API
calls and installed a development branch instead of the release.

## Fixed

### Silent branch install after a failed API call (#234)

`download_extension_from_github()` called the GitHub API with `curl -fsSL ... 2> /dev/null`.
Any failure - an HTTP 403 rate limit (60 requests per hour and IP without a token),
a proxy blocking `api.github.com`, a 404 for a private or misspelled repository -
left the response empty and was reported as `No releases found`. The tags lookup
failed the same way, and the installer downloaded `archive/refs/heads/main.tar.gz`
from `github.com`, which is not rate limited, and reported success. The installed
tree was the development branch without `.extension.checksum`, so a later
`--update` could not detect modified configuration files.

- The HTTP status of each API call is evaluated. Rate limit (403/429, with reset
  time and token hint), access denied, 404 and network/proxy errors (with the curl
  error message) abort the install with the cause.
- The fallback to the latest tag applies only when the repository itself answers
  and has no release. There is no automatic branch fallback anymore.
- `create --from-github` reports the same causes.

## Added

- `add --branch <name>` installs a branch on purpose and warns that a development
  tree is installed.
- `GITHUB_TOKEN` / `GH_TOKEN` are sent with the API calls (curl only, via
  `--config` on stdin, so the token does not appear in the process list).

## Changed

- A repository with neither a release nor a tag no longer installs `main`; the
  command fails with a hint to `--branch main`.
