# Release v1.1.3 - Unified Audit Archive Timestamp in UTC

**Release date:** 2026-11-24
**Previous version:** 1.1.2

## Summary

A patch release for the audit SQL scripts. `DBMS_AUDIT_MGMT.SET_LAST_ARCHIVE_TIMESTAMP`
reads `last_archive_time` as UTC for the unified trail and drops the offset of a
`TIMESTAMP WITH TIME ZONE`. Every script that derived the boundary from the local
clock set it off by the server's UTC offset - one hour on a server at UTC+1.
Lab-verified on 19.27 and 23.26.3.

## Fixed

### Daily archive timestamp job

`aud_init_jobs_aud.sql`: the `DAILY_UNIFIED_AUDIT_TIMESTAMP` job used
`sysdate-<retention>`. It now uses `sys_extract_utc(systimestamp) - INTERVAL '<retention>' DAY`.
The retention semantics are unchanged. The header comments of the retention scripts
say UTC now. Existing jobs keep the old action until they are re-created.

### Splunk archive timestamp sync

`aud_splunk_checkpoint_setup.sql` (K-WD) and `aud_splunk_at_detection_setup.sql` (K-AT)
computed the boundary as a `TIMESTAMP WITH TIME ZONE` in local time. On a UTC+1 server:

- the boundary was one hour late in fallback, checkpoint and detection mode
- a checkpoint less than an hour old produced a "future" timestamp and the sync
  failed with ORA-46410 (26ai)
- the never-backwards check compared the shifted stored value with the true one,
  so the boundary did not advance for an hour
- in detection mode the result depended on the session time zone of the caller,
  because `EVENT_TIMESTAMP` follows it

Both procedures now compute in UTC (`SYS_EXTRACT_UTC`, `EVENT_TIMESTAMP_UTC`) and
compare against the UTC value of the current boundary. Safety margins and the
never-backwards rule are unchanged. Re-run the setup script to replace an installed
procedure.

The lab run also exposed install blockers: the setup aborted with ORA-06502 before
creating the procedure (512-character DDL buffer), the detection script referenced
`sys.unified_audit_trail` instead of `audsys.unified_audit_trail`, and the
verification queries used column names that do not exist.
