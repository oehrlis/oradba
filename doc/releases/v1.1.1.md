# Release v1.1.1 - Updates That Roll Back, Filters That Hold

**Release date:** 2026-10-12
**Previous version:** 1.1.0

## Summary

A patch release from one fix round. It started with issue #224 (an in-place
update left a broken installation) and the open items in `tasks/open-work.md`.
Several items turned out larger than noted, and running the tests that had been
skipped since they were written found one more defect.

## Fixed

### In-place update (#224)

`oradba_install.sh --update` removed the installation before the new version was
downloaded and extracted. Any failure after that point - download, a corrupt
tarball, the integrity check - left an empty prefix next to an unused backup. The
explicit rollback after a failed verification never ran either: the detailed
`--verify-core` call exited non-zero under `set -e` first.

- The old installation is removed only after the new one is extracted.
- An EXIT trap restores the backup on any failure while a backup exists.
- `perform_update` ran inside a command substitution, so "Already running latest
  version" only ended the subshell and the installer reinstalled anyway. It is
  called directly now; `--github` and `--local` apply the same version check
  after extraction.

The `mv ... .updating: No such file` crash quoted in the issue came from an
installed 1.0.0-rc.7 and was already fixed in rc.8.

### rlwrap password filter for `sqh`

With `ORACLE_SID` set and rlwrap installed, `oradba_aliases.sh` redefined `sq` and
`sqh` as plain rlwrap calls after `oradba_standard.conf` had configured `sqh` with
completions and the `-z` password filter. With `ORADBA_RLWRAP_FILTER=true`,
passwords typed in SQL*Plus therefore still reached the rlwrap history, and `sq`
gained rlwrap against the documentation. The override is removed.

### Fallbacks that say so (#225, M7)

- Unset `ORACLE_BASE` falls back to `/u00/app/oracle` (override
  `ORADBA_DEFAULT_ORACLE_BASE`) with a WARN, instead of a silent `/u01/app/oracle`.
- The six control scripts share one log directory rule: `${ORADBA_LOG:-/var/log/oracle}`,
  `/tmp` fallback with a WARN. Before, two fell back silently, three not at all,
  and `oradba_services_root.sh` ignored `ORADBA_LOG`.
- `oradba_version.sh --verify` falls back to `shasum -a 256` and names a missing
  SHA-256 tool instead of reporting "FAILED" with 0 issues.
- An interactive install with `--prefix <base>/local/oradba` no longer overrides
  the base with the `/opt/oracle` prompt default.

### Exit codes under `set -e`

Nine sites captured `$?` on the line after the command. Latent - every caller
used `if` - and now `cmd || rc=$?`. `_oradba_path_contains` guards `${!pathvar:-}`.

## Added

- `src/doc/conventions.md`: OS groups and GIDs, filesystem layout (`/u00`
  software, `/u01` data, `/u02` archive), Oracle Home naming `product/<x.y.0.0>`.
  odb_autoupgrade 0.6.0 implements these as overridable defaults.
- `make test-clean`: the full suite with a clean environment.

## Tests and build

- Five installer tests had looked for the tarball in `build/`, where the build
  never writes it, and were always skipped. They run now - which found the
  prompt defect above.
- `build_installer.sh` stages per run and locks `dist/`; parallel builds no longer
  corrupt each other.
- Deploy Documentation is green again (synced extension pages excluded from the
  git-revision-date plugin).

## Upgrade

```bash
oradba_install.sh --update --github
```

`--update` on an installed 1.1.0 or earlier runs that old installer, without the
rollback protection. To get it already for this update, download the 1.1.1
`oradba_install.sh` from the release and run it with `--update --prefix <path>`.
