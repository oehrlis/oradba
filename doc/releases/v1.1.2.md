# Release v1.1.2 - Extension Integrity Check Fixes

**Release date:** 2026-10-16
**Previous version:** 1.1.1

## Summary

A patch release for `oradba_version.sh`. Two defects showed up when running
`version` on an installation with odb_autoupgrade and an extension update backup.

## Fixed

### `.checksumignore` patterns with a slash

The extension integrity check converts each `.checksumignore` line into an awk
regex literal. Slashes were not escaped, so a pattern such as `etc/autoupgrade.env`
or `jar/*.jar` ended the regex early and awk aborted with a syntax error. The
extension was then reported as `FAILED`, although its files were intact.
Directory patterns with only a trailing slash (`log/`, `keystore/`) were not
affected, which is why most extensions passed.

The conversion now escapes `/`. The generated expression for the odb_autoupgrade
ignore file is valid awk, and the extension verifies.

### Update backups checked as extensions

`oradba_extension.sh` leaves a `<name>_backup_YYYYMMDD_HHMMSS` directory after an
update. `discover_extensions` skips these, but the integrity check ran its own
`find` and verified them as extensions. It now applies the same rule and lists
each skipped backup by name.

## Tests

- `test_oradba_version.bats`: the generated exclusion expression for patterns with
  slashes is checked for content and runs through awk against a sample checksum
  file. The test fails on 1.1.1.

## Upgrade

```bash
oradba_install.sh --update --github
```
